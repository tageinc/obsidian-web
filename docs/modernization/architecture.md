# Implemented architecture and release boundaries

Status: approved on 2026-09-21 as recorded in [the decision package](README.md).
Implementation and final local backend, frontend, browser/accessibility and
production-build checks are complete; see [the delivery record](delivery-plan.md).
This is a frontend migration, not a Laravel business-domain rewrite. Laravel
8.83.27/PHP 8.3 remain the immediate backend baseline; upgrading the backend to
a supported Laravel release is a separate follow-up and remains a release risk.
Vue 3 alone does not make Laravel 8 supported.

The former admin management screen is now Developer Workspace at
`/developer-workspace`, authorized by `DEVELOPER_EMAIL` with no `ADMIN_EMAIL`
fallback. Historical admin terminology below and the internal `admin` feature
flag refer to this same policy; see [the current access model](../access-model.md).

Device registration and Developer Workspace uploads use the shared `FormModal`
component: a native dialog with a fixed header, scrollable body, keyboard focus
wrapping, and guarded dismissal while a form submission is pending. Firmware
and Configuration each open their own modal from New upload above release
history. Closing restores focus to that button. Native multipart endpoints,
CSRF, file limits, and developer authorization are unchanged. Validation and
handled storage failures reopen the matching modal with description/prefix
retained and focused error feedback; the file must be selected again. Success
returns to the matching history with the modal closed. The `admin` flag still
provides the existing Blade rollback path.

## Dependency decisions

The approved families are resolved in `package-lock.json`. Use Node **24.15.0**
and npm **11.8.0**, pinned in `.nvmrc`, package metadata and the Docker build.
The original host Node 24.13.1 is below the transitive `nopt` engine minimum;
use the pinned container or update the host runtime. No unreviewed major
substitution is permitted. The recorded final npm audit reports zero advisories;
this is a point-in-time dependency check, not a claim about Laravel support.

Use JavaScript SFCs and JSDoc for API payloads initially. A repository-wide
TypeScript conversion, Inertia, Nuxt, Vuex, a design-system replacement and a
form-schema library add no necessary capability to this migration.

Vue recommends Vite/Pinia for modern Vue 3 projects. Vite's currently documented
regularly patched release line is 8.3. Its generic backend integration supports
manifest-driven Laravel HTML without requiring a Laravel upgrade.

[Vite support](https://vite.dev/releases),

## Build and coexistence

1. Add Vite entries under `resources/js/entries/` and output to `public/build/`.
   A small tested Laravel 8 manifest adapter renders entry/import CSS and module
   tags. Do not assume modern Laravel's built-in `@vite` exists in this version.
   Reject missing/unexpected manifest paths; no remote production fallback.
2. New pages use a minimal Blade envelope, one pinned stylesheet and one Vue 3
   mount. Unconverted pages continue using the frozen legacy assets. Asset
   selection is per document; Vue 2 and Vue 3 never own the same DOM subtree.
3. No active workflow rendered the Vue 2 ExampleComponent. Its source, the old
   `resources/js/app.js`/`bootstrap.js` and `webpack.mix.js` are removed. Frozen
   legacy bundles may remain available during rollback, but are not loaded on
   Vue 3 pages. No new Vue 2 code or parallel Vue 2 dependency install.
4. Introduce server-side per-workflow flags (`frontend.vue3.*`) defaulting off
   during migration. A flag selects the legacy view or Vue envelope only after
   the existing route/controller authorization and data lookup execute.
5. Build in a pinned Node Docker stage with `npm ci` and `npm run build`, copy
   only production assets to PHP image. Do not copy `.env*` into the build stage,
   run Composer with frontend credentials, or expose server values via `VITE_*`.
6. Keep legacy and fingerprinted assets for the rollback window. A previous
   security-corrected image is the whole-release rollback: at least `93a3fc7`,
   including the earlier server and Redis request-log fixes plus legacy
   browser/API redaction. For old open tabs requesting lazy chunks,
   retain previous-release hashed assets at the approved serving layer; this is
   a production rollout prerequisite, not an assumption about the current image.
   A visible refresh/error message is the secondary chunk-failure path; no mutation is replayed.

This transition is **Vue 3 alongside Blade**, with frozen legacy assets where
needed, not a rewrite into one unrestricted SPA. Email templates stay Blade.

`FRONTEND_VUE3_ENABLED` is the master switch. The example environment files enable
it; installations without this setting retain the legacy fallback. Each page can override
it with `FRONTEND_VUE3_PROFILE`, `FRONTEND_VUE3_CREATE_DEVICE`,
`FRONTEND_VUE3_DEVICE_EDIT`, `FRONTEND_VUE3_DASHBOARD`,
`FRONTEND_VUE3_VIEW_DEVICE`, `FRONTEND_VUE3_AUTH`, `FRONTEND_VUE3_ADMIN`,
`FRONTEND_VUE3_PUBLIC_PAGES` or `FRONTEND_VUE3_WORKSPACE`.
Navigation follows the document's Vue/legacy asset choice. The workspace
must have all five destination flags enabled before client routing is used;
otherwise normal document navigation remains available. Flags select rendering
only and never disable server ownership/admin/verification protections.
The local app at `http://localhost:8080` has these frontend/workspace switches
enabled in its ignored environment and passed the final browser checks.
Existing server environment files are not replaced on deployment. Follow the
frontend configuration steps in `docs/github-actions-deployment.md` to enable
Vue on installations created with the older default-off example.

## Routing and server contracts

The bounded workspace consists of `/dashboard`, `/profile`, `/device-register`,
`/edit-device/:id` and `/devices/:id`. Initially each mounts independently
with normal document links. Enable client routing only once all destination
pages are migrated, authorized and regression-tested. Auth/password/verification,
admin, contact, thank-you, delta, downloads and external links use document
navigation; these are explicit route boundaries, not accidental alternatives.

- Preserve every existing Laravel route, middleware, redirect and query contract.
  `/` and `/device-manager` remain server redirects to `/dashboard`; unknown
  routes retain their server 404. No catch-all may shadow `/api`, uploads,
  verification, downloads or Livewire.
- Vue Router uses the same workspace paths and query strings. Direct reloads
  pass through Laravel. Client navigation loads allowlisted page DTOs through
  the same authenticated web GET controllers using additive content negotiation;
  ordinary HTML requests and existing `/api` contracts remain unchanged.
- Authorization must happen for each server data read/mutation. Pinia flags and
  router guards only determine presentation. Never cache permission decisions,
  a previous user's page data, or failed auth responses in the client.
- Keep current successful form POST/PUT redirects and server validation. Vue
  forms can retain native actions/CSRF/method fields during migration, using
  one common submit/feedback pattern; no need to rewrite controller business
  logic for asynchronous saves. JSON behavior is reserved for existing async
  operations and additive page loaders. Never automatically replay a mutation.
- Preserve map array vs paginator response shapes with a client adapter. Move
  graph/remote helpers into modules without averaging, resampling, polling or
  changed motor semantics. Mount/unmount/navigation must send zero remote commands.
- A destructive GET such as `/delete-device/{id}` is an explicit document action,
  never a RouterLink/prefetch target. Contract modernization is a separate ticket.

## Components, state and interaction conventions

```text
resources/js/
  entries/                 # minimal feature mounting / shared initialization
  shared/{api,components,composables,stores,utils}/
  workspace/{App.vue,router.js}/
  features/
    dashboard/ profile/ devices/ solar-tracker/ auth/ admin/ public/
```

Views coordinate requests and page state. Components take props and emit events;
they do not mutate nested props, create hidden globals or couple to unrelated
DOM IDs. Forms and field errors use local reactive state. Pinia holds only
cross-component state; graph datasets and form passwords are not global stores.
Clear user-specific memory on logout/session expiry. No auth tokens, addresses,
telemetry or form drafts in localStorage/sessionStorage/IndexedDB/service workers.

The shared client sends same-origin cookies and CSRF headers and normalizes
401/419 session expiration, 403 denial, 404/410 unavailable resources, 422 field
errors, 429 retry timing and 5xx/network failures. Because the current CSRF
handler redirects, detect unexpected HTML/login redirects before JSON parsing.
Content-negotiated 401/419 changes require backend compatibility tests.
Cancel obsolete reads and ignore out-of-order responses. Retain entered
non-secret values on validation/network failure; never retry commands or uploads
automatically. Disable duplicate submits and announce progress.

Every data view has visible loading, empty and error states with a deliberate
retry action. Inputs have associated labels, `aria-describedby`/`aria-invalid`,
an error summary and focus to the first error. Navigation restores a meaningful
heading/focus and document title; back/forward preserves query-driven state.
Dialogs require focus containment/Escape/return focus. Map popups use safe DOM
text, not interpolation of device values into HTML. Charts retain accessible
titles/units and a meaningful textual summary. Test mobile layouts and keyboard
access without changing working workflows for visual preference.

## Security prerequisites and scope gates

The inventory distinguishes intended policy from current implementation.

- Before any new bootstrap/JSON DTO: allowlist fields; hide password hashes and
  remember tokens from serialized Users; remove credential/token/full-payload
  logging in login, CSRF, request middleware and dashboard. Keep per-request
  CSRF material only in its normal transient same-origin transport, never built
  assets, persisted browser state, Redis caches or diagnostics.
- Approved and implemented: apply the documented owner/configured-admin policy
  to browser device detail/read/control routes, enforce admin management access,
  and verify email-link signatures/hash/throttling with one resend. No broader
  role model, tenant system or device-firmware authentication scheme is proposed.
- The security tests cover both frontend paths. Old non-expiring verification
  links (previously signed forever) require a fresh resend. Expired or tampered
  signatures are rejected.
  Never restore permissive checks to make an old link succeed.
- Existing mobile/firmware API security remediation and changing destructive GET
  semantics are separate follow-ups. Do not point the Vue browser client at
  those legacy endpoints to avoid proper session-backed web boundaries.

All page bootstrap responses are user-specific and must not be public/shared
HTTP cache entries. Redis is not used for page DTOs, users, credentials, device
locations, live telemetry or remote-control state in this implementation.
